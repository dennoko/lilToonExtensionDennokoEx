## What This Project Is

**DennokoEx** is a lilToon 2.x custom shader extension for VRChat avatars. It adds four extra layers on top of lilToon's standard pipeline: Reflection 2nd, Rim 2nd, Matcap 3rd, and Normal Map 3rd. The shader name is `dennokoworks/DennokoEx`.

## Build / Iteration Workflow

This is a Unity Editor package — there are no CLI build or test commands. To iterate:

1. Open the project in Unity via VRChat Creator Companion (VCC).
2. Shader changes in `Shaders/` are compiled automatically on save.
3. Inspector changes in `Editor/` recompile via Unity's domain reload.
4. To test VRCLV integration: install/remove the `red.sim.lightvolumes` package via VCC; `DennokoExVRCLVDetector` regenerates the bridge automatically.
5. To manually regenerate the VRCLV bridge: **Window > DennokoEx > Regenerate VRCLV Bridge**.
6. Before packaging/releasing: **Window > DennokoEx > Prepare for Export (Reset VRCLV Bridge)** — this resets `DennokoEx_VRCLV_Inject.cginc~` to the safe default (VRCLV=0).
7. Packed masks are generated automatically; **Window > DennokoEx > Re-pack All Masks in Project** forces a rebuild and **Window > DennokoEx > Clean Up Unused Masks** deletes generated masks nothing references (see *Packed Mask Assets* below).

## Architecture

### Shader Pipeline (`Shaders/`)

lilToon's custom shader system compiles `.lilcontainer` files (one per render mode variant) by substituting three `.lilblock` injection points:

| File | Role |
|---|---|
| `lilCustomShaderDatas.lilblock` | Declares the shader name and editor class |
| `lilCustomShaderProperties.lilblock` | Material property declarations (`_CustomXxx`) |
| `lilCustomShaderInsert.lilblock` | `#include`s `custom_insert.hlsl` — forces TBN into v2f |
| `custom.hlsl` | All fragment shader logic via `#define` hooks into lilToon's pipeline |

The `custom.hlsl` hooks execute at these lilToon pipeline points:
- `BEFORE_AUDIOLINK` → Normal Map 3rd (composites on top of lilToon's normal pipeline)
- `BEFORE_REFLECTION` → Reflection 2nd (Blinn-Phong isotropic or Kajiya-Kay anisotropic)
- `BEFORE_RIMLIGHT` → Matcap 3rd
- `BEFORE_EMISSION_1ST` → Rim 2nd

### VRC Light Volumes Bridge

VRCLV support uses a two-file indirection to avoid committing environment-specific state:

- **`DennokoEx_VRCLV_Bridge.cginc`** — committed, always shipped. Includes the inject file and exposes `DNKW_VRCLV_AVAILABLE` macro.
- **`DennokoEx_VRCLV_Inject.cginc~`** — NOT a Unity asset (`~` suffix = Unity ignores it). Auto-generated by `DennokoExVRCLVDetector.cs`. Contains the actual `#include "Packages/red.sim.lightvolumes/..."` when VRCLV is installed. Git `skip-worktree` is applied automatically so local VRCLV=1 state never leaks into commits.

In `custom.hlsl`, Reflection 2nd has two code paths gated by `#if DNKW_VRCLV_AVAILABLE`: the VRCLV path calls `LightVolumeSH` + `LightVolumeSpecular`; the fallback path uses standard Blinn-Phong against `fd.lightColor`.

### Packed Mask Assets

The shader samples only `_CustomMaskPacked`; the four `_Custom*MaskTex` slots exist purely for authoring and are stripped from the build. `DennokoExMaskPacker` bakes the slots into a PNG under `Assets/DennokoEx Generated/Masks/`.

- **Content-addressed.** The file name is `PackedMask_<hash>.png`, where the hash covers the source masks' GUIDs and content hashes. Materials baked from the same slots therefore share one file, and a duplicated material adds no new file. Nothing is ever overwritten in place.
- **`importer.userData`** holds `DennokoExPackedMask|<layout>#<signature>`. The prefix marks the file as generated (the cleanup pass never touches anything else), and the signature lets both the inspector and the NDMF pass tell a current file from a stale one without re-baking.
- **`DennokoExMaskSync`** is the scheduling layer: a one-shot silent migration on first launch, plus a deferred, coalesced bake queue. Baking imports an asset, so it must never run inside `OnGUI`.
- **NDMF** (`DennokoExPackMasksPlugin`) ships the saved PNG when its signature still matches, and falls back to `Bake(forBuild: true)` otherwise — the slots are user-facing properties that other tools can change without the inspector ever running.

`DennokoExV2` uses the same scheme with the `DennokoExV2GlobalMask` prefix and `GlobalMask_<hash>.png` names, in the same folder.

### Editor Inspector (`Editor/`)

`DennokoExInspector` extends `lilToonInspector`. Key patterns:

- **Dual-property pattern for texture-gated features** (Matcap 3rd, Normal Map 3rd): `_CustomXxxUIEnabled` (shown in UI) and `_CustomXxxEnabled` (effective, drives shader). `SyncEffectiveEnabled()` keeps them in sync — the feature is only active when UI is on AND a texture is assigned. This avoids GPU branching on empty textures. Call `SyncEffectiveEnabled` whenever either the toggle or the texture changes.
- **Copy/paste buffer**: Per-section gear menu (static dictionaries `_clipFloats`, `_clipColors`, etc.). Undo is recorded via `Undo.RecordObjects` before paste.
- **Localization**: `DennokoExLanguage.Get(key)` loads `Resources/Language/<lang>.json` (keyed by lilToon's `lilLanguageManager.langSet.languageName`), falling back to `en-US`. Add new UI strings to both `en-US.json` and `ja-JP.json`.

### Assembly Definition

`Editor/DennokoEx.Editor.asmdef` is Editor-only and references `lilToon.Editor`. All editor code is wrapped in `#if UNITY_EDITOR`.

## Shader Property Naming Conventions

All custom properties use the prefix `_Custom` followed by the feature name and parameter:
- Reflection 2nd → `_CustomRefl2nd*`
- Rim 2nd → `_CustomRim2nd*`
- Matcap 3rd → `_CustomMatcap3rd*`
- Normal Map 3rd → `_CustomNormal3rd*`

Sampler usage: all custom textures share a single `sampler_linear_repeat` to stay within the ps_4_0 16-sampler limit.
