# 永続マスクの段階的ベイク

## 動作

元の4つのマスクスロットを編集データとして保持し、合成PNGを共有する既存の形式を維持する。起動時に全マテリアルを検索・変換する処理は実行しない。

- 読み込み済みシーンとPrefab Stageの有効なRendererを順次確認する。非アクティブな階層は走査を打ち切り、Renderer.enabledがfalseの対象はベイクしない。
- マテリアルInspectorを開いた場合は、シーンで未使用でも対象にする。Inspector描画中には署名確認やアセット書き込みを行わない。
- おおむね1秒ごとに対象を再確認するため、Rendererの有効化、マテリアル差し替え、外部ツールによる編集にも追従する。Hierarchy変更、シーン追加、Undo/Redo、アセットのインポートでも再確認を予約する。
- 走査は1 updateにつき最大64ステップ／約2msで区切る。処理待ちマテリアルは重複排除し、1 updateにつき最大1マテリアルを処理する。同期インポートとGPU処理自体は分割できないので、1件のベイクが2ms以内に完了するという意味ではない。
- 同じ入力のPNGがあればベイクせずに割り当てる。待機中にRendererが無効になった場合は、自動要求を実行しない。明示的な編集・更新要求は実行する。
- コンパイル、インポート、Play Modeとその遷移、Playerビルド中は自動処理を待機する。失敗した入力は毎秒再実行せず、別入力への変更・外部インポート・手動更新で再試行する。

## 上書き更新の互換性

元マスクのプロパティ名、RGBA配置、保存先、v1署名形式は変更しない。移行済みフラグは旧APIとして残すが、自動移行の条件には使わない。

1. 旧シェーダーを新シェーダーで上書きしても、保存済みの元マスクを利用して生成する。
2. 合成マスクが未設定、旧一時プレビュー、欠落、または古い入力の結果であれば、必要になった時点で更新する。
3. 正しい署名を持つ旧バージョンのPNGは、旧マテリアル別の保存場所にあっても再利用する。上書き更新だけで全PNGを作り直さない。
4. 非アクティブ・未使用のマテリアルは、そのまま保持し、有効化・配置・Inspector表示時に自動移行する。
5. 最後の元マスクを取り除いた場合は、生成物／一時プレビューの参照を解除する。手動指定された永続の合成マスクだけを利用するマテリアルは維持する。

移行フラグに依存しないため、プロジェクト復元、別バージョンからの再更新、移行中断後にも同じ判定で修復できる。生成後のマテリアル変更は通常の保存対象になる。未保存で終了して割り当てが失われても、次回は既存のPNGを再利用できる。

## ビルドと生成物の寿命

NDMFのTransforming段階から`DennokoExMaskBuild.Pack`を呼ぶ。ビルド側では初期非アクティブの衣装も処理し、必要ならビルド用テクスチャを生成する。編集用PNGの生成や元マテリアルの編集は行わない。元マスクが無くなった場合もクローン側で古い生成マスクを解除する。必要なベイクに失敗した場合は処理を中止する。

PNGは永続マテリアルから参照されるため、非表示になっただけでは破棄しない。古いPNGの削除は明示的なクリーンアップ操作で行う。Material・Scene・Prefabに限定せず全アセット種別の依存と、ロード済みオブジェクトの依存を調べる。このツールがセッション中に使用・置換した生成物はUndoのために保護し、ドメインリロードでも保護を維持する。候補が保護されている場合はUnity再起動後に整理できる。

保存先に異なる所有マーカーのファイルがある場合は、ユーザーの差し替え画像を上書きせずエラーとする。

## 検証

`Tools~/MaskBakeTests/run.ps1`は独立した一時Unityプロジェクトを作る。既存プロジェクトのシーンや生成PNGをテスト用に変更しない。

- 第1セッション：合成プロパティのない旧シェーダーでマテリアル／シーンを保存し、旧形式の永続PNGも準備する。
- 第2セッション：同一シェーダーファイルを上書きし、自動移行、対象の絞り込み、追加ベイク、4チャンネルのGPU出力、元画像再インポート、Undo/Redo、ビルド用クローン、Prefab Stage、待機の取り消し、削除と上書き保護を検証する。
- 第3セッション：再起動後にPNGが追加生成・再書き込みされず、参照が有効なことを確認する。

テストはUnity 2022.3.22f1を使用し、GPUベイクのため`-nographics`は付けない。結果とログは一時プロジェクトに残る。NDMFアダプターは実プロジェクトのNDMFアセンブリに対するコンパイルでも確認する。

## 範囲と制約

全件再生成メニューは明示的な同期処理であり、起動時には呼ばれない。シーン探索は画面内判定ではなく、有効なRendererを基準とする。モデル内・ビルド出力のサブアセットやPackages配下のマテリアルは、編集時の自動PNG生成対象にしない。

アニメーションで後から差し替えるマテリアルの網羅、動的に生成・更新される元テクスチャの永続識別、生成PNG自体の改変検知は、この変更では拡張していない。ビルド側の対象は従来どおりビルド時点のRenderer.sharedMaterials。クリーンアップも、文字列での動的ロードや外部ツール独自の未保存Undo状態までは解析しない。
